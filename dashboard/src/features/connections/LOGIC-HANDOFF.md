# Connections logic handoff (T-19–21)

`useConnectionsController()` in `useConnectionsController.ts` owns credential catalogue/status polling, status refresh, action decisions and callbacks for Set, Disconnect, cleanup retry and key repair. `connections.ts` exports the slot model, server-capability/permission mapping, complete-bundle validation and root cleanup proof predicate.

The consumer supplies confirmation and form state. It must clear secret values immediately after each submission settles. Secret bundles are sent only in the request body and are never saved in browser storage or receipt metadata. A timeout leaves the result unknown; provide a fresh same-user submission only after reviewing the operation, and never auto-replay a secret bundle. Reuse a request idempotency key only with the identical request and unchanged versions. Each callback rechecks current `manage_credentials` permission, slot action availability, and reviewed slot/control/root operation versions before sending.

Set/Disconnect/retry/repair include the version fields and idempotency key required by OpenAPI. A non-secret per-slot/action lock is scoped to API, principal, bot, and reviewed versions. It stays in place after HTTP acceptance until that exact receipt is terminal, so a new key cannot duplicate an applying operation. For an unknown timeout, the UI must require fresh explicit review and re-entry of the same request body with the same idempotency key; `reviewUnknown` returns that key and confirms versions remain unchanged. The controller never retains the credential bundle. A changed version creates a new review decision. Cleanup retry and key repair must target the root cleanup operation, use current slot/control/operation versions, and follow the root receipt. Only a `succeeded/removed` root receipt with all four proof fields true establishes cleanup completion. A child receipt is not sufficient.

The credential status endpoint emits `status="connected"` only when its server snapshot has a fresh heartbeat/availability observation, matching owner UUID/generation and `credential_versions[connector] === slot.version` (`admin_credentials.py`). The slot `observed_at` identifies that evidence time. The frontend pairs it with a fresh runtime observation and only shows Connected while the slot evidence is at most five seconds old relative to runtime `server_time` and both cached query results are at most five seconds old; credential status polls every five seconds. A separate owner credential-version field is unnecessary because the server status is the proof. Hosted/runtime acceptance remains outside the local/mock TODO scope.

Logic tests cover permission/action gating, managed versus environment source, Stop acknowledgement, stale/unavailable status, required bundle fields, every mutation payload/version/root ID, duplicate prevention while pending and accepted, terminal receipt unlock, timeout without secret persistence, explicit same-key recovery after fresh review, receipt reopening by root ID, final-proof requirements, and out-of-order exchange responses. Mock tests do not prove restart behavior or actual exchange cleanup; those remain part of integrated/runtime acceptance.
